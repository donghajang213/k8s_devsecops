# ADR 0004: `:latest` 고정 태그 사용 — 알려진 한계

## 상태
승인됨 (알려진 한계로 명시적으로 남겨둠)

## 배경
CI가 이미지를 빌드해서 `:latest`와 `:<git-sha>` 두 태그로 Artifact Registry에 푸시하고,
K8s 매니페스트(`api.yaml`, `migrate-job.yaml`)는 `:latest`를 참조한다.

## 문제
실제로 겪은 문제: CI가 새 이미지를 `:latest`로 푸시해도, `Deployment`의 파드 템플릿에
적힌 이미지 문자열(`...api:latest`)은 이전과 글자 그대로 동일하기 때문에 K8s/ArgoCD가
"바뀐 게 없다"고 판단해 롤아웃을 트리거하지 않는다. `imagePullPolicy: Always`는 "새로
스케줄되는 파드는 항상 최신을 받아온다"는 뜻이지, "떠 있는 파드를 능동적으로 갱신한다"는
뜻이 아니다. 그래서 이미 떠 있는 파드는 옛날 이미지를 계속 쓰고 있었다 (실제로 이 때문에
새로 추가한 `/metrics` 엔드포인트가 한동안 반영되지 않았다).

지금은 `kubectl rollout restart deployment/api`로 수동으로 갱신했다.

## 올바른 해결책 (이번엔 적용 안 함)
- CI가 이미지를 `:<git-sha>`처럼 불변 태그로 빌드한 뒤, 그 태그로 K8s 매니페스트 파일
  자체를 고쳐서 git에 커밋(예: `sed`+`git push`, 또는 Argo CD Image Updater 애드온)하면
  Deployment 스펙 자체가 매번 바뀌어서 자동으로 롤아웃된다.

## 왜 지금은 안 했는지
GCP 크레딧/기간 제약 속에서 CI가 매니페스트를 직접 고쳐 커밋하는 파이프라인까지 구성할
시간이 부족했다. `:latest` + 수동/주기적 `rollout restart`로 당장은 충분하다고 판단했다.

## 트레이드오프
- 배포가 "완전 자동"이 아니다 — 이미지가 바뀌었는데도 수동 재시작 전까지는 옛 버전이
  떠 있을 수 있다는 걸 인지하고 있어야 한다.
- 불변 태그 기반으로 정리하면 "이 커밋이 정확히 이 이미지를 배포했다"는 추적성도 같이
  얻을 수 있어서, 다음 단계로 남겨둔다.
